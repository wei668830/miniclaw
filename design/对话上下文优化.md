## 一、计划说明

### 1.1 背景

`./design/记忆优化.md` 已落地上下文预算机制：`utils/context.py` 提供 `estimate_messages_tokens` / `check_budget` / `get_context_budget` / `shrink_messages`，`main.CommandLineInteraction._ensure_context()` 在每轮 LLM 调用前按 soft/hard 阈值自动精简（soft 裁剪较早工具输出、hard 精简记忆并重建）。

但**阈值本身**此前只能通过一组**全局环境变量**静态配置（`MINICLAW_CONTEXT_WINDOW` 默认 128000 等），存在两个短板：

1. **与模型/接入点解耦**：切换到大窗口模型（如 1M）时，框架不会自适应，仍按 128000 计算，**过早触发精简**，浪费可用上下文。
2. **无运行期调整能力**：只能改 `.env` 重启，无法会话内快速试调（如按当前任务临时放大窗口）。

本计划在**不改动原有阈值语义**的前提下，为阈值引入 **「`.env` 持久化 + 斜杠命令运行期覆盖」** 双向配置能力，并给出 1M 窗口的落地预设。

### 1.2 现状问题（评审结论）

| 编号 | 问题 | 说明 |
| --- | --- | --- |
| P1 | 阈值是全局单值，与模型解耦 | `get_context_budget()` 无参，读全局环境变量，切换模型不切换窗口/阈值 |
| P2 | 无运行期调整能力 | 改阈值须改 `.env` 并重启 |
| P3 | 无优先级/回退机制 | 仅「环境变量 → 默认」两级，缺运行期覆盖与一键回退 |
| P4 | `/context` 无设置入口 | 此前仅「查看状态 + `shrink`」，无法读写阈值 |
| P5 | 大窗口模型无预设 | 1M 等模型需手工改 `.env`，无成套预设 |
| P6 | 覆盖语义不清晰 | 用户不知当前值来自 `.env` 还是覆盖 |

### 1.3 决策

采用 **三级优先级**：**运行期覆盖 > `.env`/环境变量 > 内置默认值**。

- **持久化层**：`.env`（由 `load_dotenv()` 启动加载，写入 `os.environ`，`EnvVarLoader` 读取）——负责长期/按模型配置。
- **运行期层**：新增**覆盖注册表**（进程内存，不落盘），由 `/context` 子命令读写——负责会话内快速试调，`reset` 一键回退。
- **解析入口**：统一收敛到 `get_context_budget()`，对现有调用方零侵入（签名不变）。

### 1.4 目标

- 支持 4 个预算参数（window / soft_ratio / hard_ratio / reserve）的 `.env` 持久化与运行期覆盖。
- 新增 `/context` 子命令：查看 / 设置 / 回退，带合法性校验。
- 保持 `soft < hard ≤ window - reserve` 不变式与既有默认值。
- 提供 1M 窗口的成套预设写入 `.env`。

## 二、方案设计

### 2.1 三级优先级解析（`utils/context.py`）

`get_context_budget()` 改为按「覆盖 > 环境变量 > 默认」逐项解析：

- 值域定义集中在一张表：`_BUDGET_FIELDS = {window, soft_ratio, hard_ratio, reserve} → (环境变量名, 类型)`。
- 解析规则：命中 `_RUNTIME_BUDGET_OVERRIDES` 则取覆盖值；否则按类型走 `EnvVarLoader.get_int / get_float`，回退内置默认。
- 后续仍执行原有不变式校验（`soft < hard`、`hard ≤ window - reserve`），异常回退默认。

### 2.2 运行期覆盖注册表

新增模块级注册表与三个函数：

- `set_budget_override(name, value)`：设置覆盖（name ∈ window/soft_ratio/hard_ratio/reserve，未知名抛 `KeyError`）。
- `clear_budget_overrides()`：清空覆盖，回退到 `.env` / 默认。
- `get_budget_overrides()`：返回覆盖项副本（只读，供状态展示）。

覆盖**仅作用于当前进程、不落盘**，语义上等价于「进程内最高优先级的环境变量」。

### 2.3 `/context` 子命令（`cli/main.py`）

将 `_cmd_context` 扩展为子命令式，新增 `_apply_context_override` 与 `_print_context_status`：

| 子命令 | 行为 |
| --- | --- |
| `/context` | 打印状态表 |
| `/context shrink` | 立即裁剪较早工具输出（沿用原逻辑） |
| `/context window <n>` | 运行期设上下文窗口（正整数） |
| `/context soft <ratio>` | 运行期设软阈值比例（0~1，须 < 当前 hard） |
| `/context hard <ratio>` | 运行期设硬阈值比例（0~1，须 > 当前 soft） |
| `/context reserve <n>` | 运行期设输出预留 token（≥0） |
| `/context reset` | 清除覆盖，回退 `.env`/默认值 |

校验策略：类型/范围校验（`window>0`、`reserve≥0`、比例开区间）+ 关系校验（`soft < hard`）；非法输入即拒绝并给出原因，**不修改现有值**。设置成功后即时回显新的 `soft/hard/window`。

### 2.4 状态表增强

`/context` 状态表在原有基础上新增两行：

- **有效比例 soft/hard**：由 `soft/window`、`hard/window` 反算，直观反映实际水位。
- **运行期覆盖**：列出当前覆盖项，或显示「（无，使用 .env/默认）」，明确取值来源。

### 2.5 `.env` 1M 预设

在 `.env` 增补上下文预算块（1M 窗口）：

```
MINICLAW_CONTEXT_WINDOW=1000000
MINICLAW_CONTEXT_SOFT_RATIO=0.6
MINICLAW_CONTEXT_HARD_RATIO=0.85
MINICLAW_CONTEXT_RESERVE_TOKENS=8192
```

生效结果：`soft=600000`、`hard=850000`（`window-reserve=991808 > 850000`，无截断）。`reserve=8192` 对齐 DeepSeek 8K 输出上限。

### 2.6 rich markup 转义修复

自测发现：`/context` 未知子命令的用法串以 `[shrink|...]` 开头，被 rich 当作 markup 标签吞掉，提示被截断。已转义开括号（`\[`），现可完整显示。

## 十、风险与回滚

| 风险 | 影响 | 缓解 / 回滚 |
| --- | --- | --- |
| 运行期覆盖语义被误解为持久化 | 重启后失效，用户困惑 | 命令回显明确「仅当前进程生效，如需持久化写入 .env」 |
| 大窗口下比例触发过晚 | 单次工具输出爆炸前未触发软裁剪 | 可用 `/context soft <更小比例>` 或调小 `hard_ratio`；后续可引入绝对阈值兜底 |
| 覆盖值使 `soft≥hard` | 解析回退默认、覆盖被忽略 | 命令层已做关系校验并拒绝，避免静默回退 |
| 非 OpenAI tokenizer 估算偏差随规模放大 | 1M 级别估算误差增大 | 已知局限；可后续引入估算校正系数（未在本次范围） |
| 误删/误改核心文件 | 启动失败 | 每步 `py_compile`；必要时按 git 回滚 |

## 十一、与记忆优化方案的执行关系

- 本方案是 `./design/记忆优化.md` 的**配置化增强**：不改动预算判定与精简算法，仅新增阈值的读取层级与交互入口。
- 与 `./design/会话推进机制优化.md` 协同：二者共同约束「轮次上限」（工具循环）与「token 预算」（soft/hard），本方案让后者可按模型/会话灵活配置。
- 后续可衔接项（未在本次范围）：按模型名注册表自动推断窗口、非 OpenAI tokenizer 估算校正、大窗口绝对阈值兜底。
