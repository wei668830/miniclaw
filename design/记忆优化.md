## 一、计划说明

### 1.1 任务目标

为 MiniClaw CLI 的记忆（Memory）处理逻辑制定并落地加强方案。核心目标：

> **当整个会话上下文（`self.messages`）超过模型上下文窗口限度时，通过 memory 机制最大限度恢复对话、保证任务不中断。**

当前 `CommandLineInteraction.stream()` 直接把完整的 `self.messages` 交给 `self.client.stream(...)`，`Memory.condense()` 只能手动触发且一次性提交全部历史。当工具输出（文件内容、命令输出、子代理结果）不断追加到 `messages` 后，上下文必然溢出，溢出后「精简调用自身也溢出」，任务被迫中断。本计划通过 7 个组件修复 7 个关键问题（P1–P7），使上下文管理由"手动、无感知、易失败"变为"自动、可观测、可自举、可恢复"。

### 1.7 风险与回滚

| 风险 | 影响 | 缓解 / 回滚 |
| --- | --- | --- |
| tiktoken 未安装或模型名不被识别 | 估算失败 | 自动回退启发式估算（CJK 1.0 / ASCII 0.25 系数），不抛异常 |
| 自动精简引入额外 LLM 调用，增加耗时与成本 | 响应变慢 | 仅在 soft/hard 触发时精简；soft 采用异步后台精简，hard 即时精简 |
| 精简丢失关键信息导致任务跑偏 | 任务中断 | 结构化模板强制保留计划路径 / 待办 / 文件路径 + 保留最近 N 轮原文 |
| `main.py` 改动较大破坏原有流程 | 无法启动 | 每步骤后 `py_compile` 校验；保留原 `_condense_memory()` 作为回退路径 |
| 工具输出落盘占用磁盘 | 磁盘增长 | 落盘文件名含 uuid 且写入会话 id 目录，可在 `stats()` 中统计；后续可加清理策略 |

### Phase 1：组件1 上下文预算估算模块（P1）

#### S1.1 新建 `src/miniclaw/utils/context.py`（估算核心）
- 目标：创建模块骨架并实现 `estimate_text_tokens(text: str) -> int`。
- 工具：`write_file`（单次，仅写 1 个文件）
- 具体操作：
  - 模块 docstring 说明用途与回退策略。
  - `try: import tiktoken except ImportError: tiktoken = None`，模块级 `_ENCODER` 惰性加载（`tiktoken.get_encoding("cl100k_base")`，异常时置 `None`）。
  - `estimate_text_tokens(text)`：`text` 为空返回 0；优先 `len(_ENCODER.encode(text))`；编码器不可用时使用启发式：CJK 字符（`\u4e00-\u9fff` 等）计数 × 1.0，ASCII 字符 × 0.25，其余 × 0.6，向上取整。
  - 缩进 4 空格，文件头 `# -*- coding: utf-8 -*-` 不需要，使用 `from __future__` 亦不需要。
- 校验方法：S1.4 执行 `python -m py_compile src/miniclaw/utils/context.py` 通过；S1.5 执行导入与估算调用无异常。
- 依赖：S0.1–S0.6（已完成） ｜ 优先级：**P0**

#### S1.2 追加消息级估算函数
- 目标：实现 `estimate_message_tokens(msg: dict) -> int` 与 `estimate_messages_tokens(messages: list) -> int`。
- 工具：`append_file`
- 具体操作：
  - `estimate_message_tokens`：拼接 `role`、`content`（`str` 或 `list` 时逐块取 `text`）、`name`、`tool_calls`（`json.dumps(..., ensure_ascii=False)`）、`reasoning_content`，逐项调用 `estimate_text_tokens` 求和，并加固定开销常量 `MESSAGE_OVERHEAD_TOKENS = 4`。
  - `estimate_messages_tokens`：`sum(estimate_message_tokens(m) for m in messages)`；对非 dict 元素跳过并 `logger.debug` 记录。
- 校验方法：S1.5 断言 `estimate_messages_tokens([{"role": "user", "content": "你好"}]) > 0`。
- 依赖：S1.1 ｜ 优先级：**P0**

#### S1.3 追加预算配置与 `check_budget`
- 目标：实现预算阈值读取与判定。
- 工具：`append_file`
- 具体操作：
  - 常量：`DEFAULT_CONTEXT_WINDOW = 128000`、`DEFAULT_SOFT_RATIO = 0.6`、`DEFAULT_HARD_RATIO = 0.85`、`DEFAULT_RESERVE_TOKENS = 4096`。
  - 函数 `get_context_budget() -> tuple[int, int, int]`：用 `EnvVarLoader.get_int / get_float` 读取 1.4 节环境变量，计算 `soft = int(window * soft_ratio)`、`hard = int(window * hard_ratio)`，并保证 `hard = window - reserve` 的上限约束、`soft < hard`（否则回退默认）。

## 六、补充：会话恢复入口（针对"指定会话人工恢复"）

> 本节为评审补充：原方案（Phase 1–8）已具备持久化会话历史的**底层能力**（`HistoryStore.load_all/tail/stats` + 记忆文件 + `active_plan.json`），但**缺少面向用户的"按会话恢复"入口**，且会话元数据未持久化，无法在崩溃后自动定位到最近会话。本节补齐该能力。

### 6.1 会话元数据持久化（崩溃定位）

- 新增状态文件：`~/.miniclaw/state/current_session.json`。
- 字段：`session_id`、`history_path`（JSONL 绝对路径）、`memory_file`、`active_plan`、`started_at`、`updated_at`、`clean_shutdown`（布尔）。
- 更新时机：
  - `CommandLineInteraction.__init__` 启动时写入（`clean_shutdown=false`）。
  - 每轮对话结束（`stream()` 返回前）刷新 `updated_at`；或每追加 N 条消息刷新一次。
  - 正常退出（`/quit`、`KeyboardInterrupt`、`EOFError`）时置 `clean_shutdown=true`。
- 用途：启动时若发现 `clean_shutdown=false`，说明上一次会话**异常退出**，在欢迎信息中提示：`检测到上次会话未正常结束（session_id=...），可使用 /session-resume <session_id> 恢复`。

### 6.2 新增会话恢复命令（面向用户）

| 命令 | 说明 | 关键行为 |
| --- | --- | --- |
| `/session-list [N]` | 列出最近 N 个会话（默认 10） | 扫描 `~/.miniclaw/memory/raw/*.jsonl`，展示 `session_id / 消息数 / 最后更新时间 / 首条与末条用户输入摘要`；标记哪个是当前活跃会话 |
| `/session-load <session_id>` | 加载指定会话到内存上下文 | 读取该会话 JSONL → 逐条回放进 `self.messages` → 恢复 `self.session_id`、`self.memory_file`、`self.active_plan_path`；**不自动接续执行**，仅恢复上下文供用户查看/继续 |
| `/session-resume <session_id>` | 恢复并接续执行指定会话 | 在 `/session-load` 基础上：自动执行一次分块精简 → `_rebuild_messages_from_memory()`（摘要 + 活跃计划 + 未完成步骤 + 最近 tail）→ 注入"从中断处继续执行未完成步骤"指令并进入 `stream()` |
| `/session-export <session_id> [path]` | 导出会话为可读 Markdown | 将 JSONL 渲染为 `用户/AI/工具调用` 的可读文档，便于人工核对与归档 |

### 6.3 与既有命令的关系

- `/history N`：仅查看**当前内存**最后 N 条（原有语义不变）。
- `/memory <file>`：切换**记忆摘要文件**（原有语义不变）。
- `/memory-list`：列出**记忆摘要文件**（原有语义不变）。
- 新增的 `/session-*` 系列面向**完整原始会话（JSONL）**的列表/加载/恢复/导出，二者互补。

### 6.4 异常退出的自动兜底

1. 启动检测 `current_session.json.clean_shutdown == false` → 打印恢复提示（不自动恢复，避免误操作）。
2. 崩溃前的最后一条用户输入若无对应 AI 回复，恢复时 `/session-resume` 会提示"上一轮未完成"，并从该用户输入重新驱动。
3. 恢复过程与正常流程共用 `_ensure_context()` / `_condense_and_rebuild()`，确保恢复后立刻满足上下文预算。
