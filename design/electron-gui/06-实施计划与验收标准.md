### M1 · 会话化后端（1–2 天）
- [ ] 新增 `app/models.py`（Pydantic 请求/响应模型）。

- [ ] 抽取共享逻辑：`utils/common.py::scan_skills`、`ChatSession.append_user_message`、`ensure_context`。
- [ ] 改造 `routers/llm_router.py`：`/api/chat`、`/api/chat/stream`（会话化 + 复用 `run_stream_round`）。

### M4 · 技能/设置面板（1–2 天）

## 四、整体验收标准

### 功能
- [ ] 一键 `miniclaw ui` 打开桌面窗口，自动连上后端。
- [ ] 能与 Agent 流式对话，正确渲染文本 / 思考 / 工具调用与结果 / 完成徽标。
- [ ] 会话：新建、列出、加载、恢复、导出均可视化操作。
- [ ] **技能：通过对话方式（斜杠命令 / 面板）加载；加载后下一条消息生效；本会话不可卸载；新建会话可重置。**
- [ ] 配置：切换模型、采样参数、运行模式、联网搜索开关均即时生效。
- [ ] 上下文：可查看 token 占用并做运行期覆盖/重置。

### 一致性（与 CLI 对齐）
- [ ] 技能加载/注入/记账逻辑与 CLI **同一份实现**（或等价），语义一致。
- [ ] 斜杠命令语义与 `cli/commands.py` 一致。
- [ ] `miniclaw server`、`miniclaw cli` 行为不变。

### 工程
- [ ] 前端工程根目录为 `./frontend`。
- [ ] 后端接口改造位于 `./src/miniclaw/app`。
- [ ] `__main__.py` 新增 `ui` 启动方式。
- [ ] 前后端类型契约一致（建议 OpenAPI 生成）。

### 稳定性
- [ ] 退出应用无残留后端进程；**UI 关闭（含崩溃/被强杀）后端同步销毁**。
- [ ] **单实例**：重复启动不产生第二个窗口 / 第二个后端。
- [ ] 流式中断（停止）后后端连接正确释放。
- [ ] 后端异常时前端可感知并可重启后端。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| `CommandLineInteraction → ChatSession` 抽取涉及 CLI 稳定性 | CLI 回归风险 | 采用「先封装、后抽取」两步走；M1 先用 `app/runtime.py` 薄封装，M6 再合并；全程跑 CLI 回归 |
| SSE 使用 POST，原生 `EventSource` 不支持 | 前端实现成本 | 用 `fetch + ReadableStream` 解析（已有 `chat_stream.html` 参考） |
| Electron 体积大 | 安装包体积（仅打包场景） | 一期不打包；若后续需要分发，评估 Tauri 减体积 |
| Python 后端与 Electron 生命周期不同步 | 进程残留/僵尸 | 统一「谁拉起谁关闭」；UI 所有退出路径（关窗/退出/崩溃）均销毁后端；后端看门狗（父 PID + stdin EOF）兜底；超时强杀用**句柄级** kill，禁用全局 python 杀 |
| 多实例导致端口冲突/双后端 | 资源冲突、状态错乱 | Electron `requestSingleInstanceLock()` + 运行态锁文件 `miniclaw-ui.lock`；7909 占用时按孤儿后端回收或回退端口 |
| 技能 `SKILL.md` 过大 | 上下文膨胀 | 加载时提示大小；纳入 `ensure_context` 预算策略 |
| 网关对长消息限制 | 请求失败 | 技能走用户消息、system 保持短指令（沿用现有做法） |
| 跨平台路径/可执行差异 | 打包失败（仅打包场景，非一期） | CI 分平台构建；`_electron_cmd` / `pythonExe()` 做平台分支 |
| Token 泄露 | 安全 | 仅进程内传递、`127.0.0.1` 绑定、一次性随机、退出即失效 |
