# MiniClaw 桌面应用（Electron）设计方案

> 文档类型：设计方案（design）
> 创建时间：2026-10-10
> 代码根目录：`MiniClaw`
> 关联实现：`./frontend`（前端工程）、`./src/miniclaw/app`（后端接口）、`./src/miniclaw/__main__.py`（启动入口）

---

## 一、方案一句话概述

为 MiniClaw 增加一个 **Electron 桌面应用**：

- **前端**：`./frontend`（Electron 主进程 + React/Vite 渲染进程），提供聊天、会话、技能、设置等可视化交互。
- **后端**：复用并扩展 `./src/miniclaw/app` 的 FastAPI 服务，暴露「会话 / 流式聊天 / 技能 / 配置 / 运行模式」等接口。
- **启动**：`src/miniclaw/__main__.py` 新增 `ui` 子命令，一键拉起「后端服务 + Electron 窗口」。
- **技能机制**：**完全沿用 CLI 的对话式加载**——技能以 `SKILL.md` 全文注入到用户消息中，加载后不可移除，只能通过**新建会话**重置。

## 三、关键约束（务必遵守）

1. **技能加载必须走「用户对话」通道**：不得改 system prompt；`SKILL.md` 全文以文本形式拼进用户消息（与 `cli/main.py::_append_user_message` 一致）。
2. **技能不可卸载**：本会话内一旦加载即常驻；仅「新建会话」重置（与 CLI 的 `skills_loaded` 语义一致，见 `cli/main.py::_init_messages`）。
3. **前端工程根目录固定为 `./frontend`**。
4. **后端接口改造限定在 `./src/miniclaw/app`**（允许抽取共享工具到 `src/miniclaw/utils`、`src/miniclaw/agents`）。
5. **`src/miniclaw/__main__.py` 需新增界面启动方式**（`miniclaw ui`）。
6. **前端不得用 shell 杀死 Python 后端进程**：后端进程 PID 由启动方（Electron 主进程 / `__main__`）持有，退出时优雅关闭。
7. **只允许单实例**：Electron `requestSingleInstanceLock()` + 运行态锁文件，重复启动不产生第二个窗口/第二个后端。
8. **UI 关闭 ⇒ 后端同步销毁**：关窗、退出、崩溃、被强杀等所有路径下后端都须在秒级内退出（后端看门狗兜底），不留孤儿。

## 四、非目标（本期不做）

- 不做移动端 / Web 公网部署形态。
- 不做多用户 / 账号体系（仍是单机、单用户本地应用）。
- 不重写 Agent 核心（`agents/`、`cli/stream_runner.py` 等），仅做复用与薄封装。
- 技能加载**不提供卸载/禁用按钮**（这是刻意设计，见文档 03）。
- **一期不做打包分发**：以源码 + 依赖环境运行（`miniclaw ui`，前置本机已装 Python/Node）；打包（electron-builder + PyInstaller）仅在需面向非技术用户分发时再评估。
